# Reveal Candidate / Разгляди кандидата



## Монетизация

### Идеи
- **SaaS для HR**: рекрутер платит за доступ к боту и отчётам по кандидатам
  - подписка (месяц/год) или оплата за кандидата
  - нужно: личный кабинет рекрутера, биллинг (Stripe / ЮKassa), хранение результатов
- **White-label**: продавать под брендом компании-клиента
  - нужно: мультитенантность, кастомизация вопросов и критериев
- **API**: компании интегрируют оценку в свои HR-системы
  - нужно: REST API с авторизацией, документация

### Что нужно в первую очередь
- Персистентность (MongoDB) — без неё ни один вариант монетизации не работает
- Разделение ролей рекрутер/кандидат (см. п.3 ниже)
- Деплой (см. п.2)

### 3. Мультипрофессиональные анкеты

Поддержка нескольких профессий (официант, бариста, кассир, оператор колл-центра, бортпроводник и др.).

**Архитектура:** промпт собирается динамически.
- Общий каркас (4-уровневая модель Зеер/Климов/Марков, шкала 1–5, формат вывода) — один на всех.
- Профессиональный конфиг = вводная строка + 4 вопроса + поведенческие примеры на каждом уровне I–IV.
- В промпт вставляются примеры только выбранной профессии → размер промпта не растёт с числом профессий.

**Размер промпта:**
- Текущий ASSESSMENT_SYSTEM_PROMPT ≈ 1500–2000 токенов.
- Примеры для одной профессии ≈ +500–1000 токенов.
- Итого на запрос ≈ 2000–3000 токенов — комфортно для большинства моделей.
- Проверить контекстное окно `trinity-large-preview:free` на openrouter.ai.
- theory.txt (267KB) не используется — он справочник для разработки анкет, не для промпта.

**Что нужно сделать:**
1. Создать структуру `ProfessionConfig` (название, вопросы, примеры по уровням)
2. Перенести текущий официантский конфиг в эту структуру
3. Добавить 2–3 новых профессии
4. Рекрутер выбирает профессию при создании вакансии

### 4. Разделение интерфейсов
Разделить роли: **рекрутер** (видит результаты, управляет вопросами) и **кандидат** (проходит интервью).
- Рекрутер генерирует одноразовую ссылку `t.me/bot?start=TOKEN` и отправляет кандидату
- Кандидат переходит по ссылке и сразу попадает в нужный флоу (профессия подтягивается из токена)
- Рекрутер получает отчёт по каждому кандидату
- Нужна персистентность (MongoDB уже в зависимостях, не подключена)

## Дополнительные идеи (от Claude)

- **PDF-отчёт** — рекрутер получает оформленный PDF по кандидату для архива или передачи нанимателю (`puppeteer` или `pdfkit`)
- **Голосовые ответы** — транскрибировать войсы через OpenAI Whisper, анализировать как текст; кандидату удобнее говорить, чем печатать
- **Нормирование по пулу** — после накопления N кандидатов показывать percentile: «лучше 78% кандидатов на эту позицию» (нужна персистентность)
- **Дашборд рекрутера** — веб-интерфейс: список кандидатов с баллами, фильтр по профессии и дате
- **Флаг фальсификации** — вынести в отдельное поле отчёта 🚩 «Обнаружены маркеры фальсификации», чтобы рекрутер видел сразу
- **Повторное прохождение** — детектировать повторные попытки по user_id, блокировать или помечать результат
- **Интеграция с HH.ru / Superjob** — автоматически отправлять ссылку на интервью откликнувшимся кандидатам
- **Blind hiring** — рекрутер видит баллы до имени кандидата, снижает предвзятость
- **Напоминания** — если кандидат начал интервью и не завершил, бот присылает напоминание через 24 часа
- **Комментарий рекрутера** — после просмотра результата рекрутер может добавить свой комментарий и поставить финальный статус (принят / отклонён / на доп. собеседование)
- **A/B тест вопросов** — запускать разные варианты вопросов по профессии и сравнивать качество получаемых ответов
- **Экспорт в CSV** — выгрузить всех кандидатов за период в таблицу для анализа в Excel/Google Sheets
